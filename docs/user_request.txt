# PROMPT MAESTRO — DESARROLLO Y DESPLIEGUE DE AUDRITHM

Actúa como un equipo de ingeniería de software compuesto por un arquitecto de soluciones, desarrollador senior Python, especialista en algoritmos, QA Automation Engineer, ingeniero DevOps, diseñador UX/UI y asesor técnico de documentación académica.

Tu misión es construir, probar, documentar y preparar para producción una aplicación web llamada **AudRithm — Laboratorio de Análisis de Algoritmos**.

No quiero únicamente una explicación, un prototipo visual o fragmentos de código. Quiero un proyecto real, funcional, modular, ejecutable, versionado en GitHub y desplegable públicamente.

Si cuentas con acceso autorizado a GitHub y Streamlit Community Cloud, realiza el despliegue y verifica la URL pública. Si no tienes acceso, deja la aplicación completamente preparada y explícame únicamente los pasos de autenticación y publicación que debo completar.

## 1. Contexto académico

Este proyecto corresponde a una actividad de una maestría en tecnología relacionada con el análisis y diseño de algoritmos.

La entrega inmediata es la **Bitácora 1**, cuyo algoritmo asignado es:

**Subarreglo de suma máxima (Maximum Subarray Problem).**

Debemos implementar y comparar:

- Algoritmo de Kadane: O(n).
- Algoritmo de fuerza bruta optimizada mediante sumas acumuladas: O(n²).

El proyecto debe demostrar correctitud, analizar complejidad, realizar pruebas automatizadas y ejecutar experimentos reproducibles.

También queremos construir una aplicación web que permita visualizar los algoritmos, las pruebas y las gráficas mediante un enlace público.

IMPORTANTE: la aplicación web es una mejora de presentación. No reemplaza los entregables académicos obligatorios.

El nombre AudRithm se utilizará como marca del aplicativo y podrá evolucionar posteriormente hacia una plataforma inteligente de auditoría de algoritmos. No implementar un agente de IA real en esta primera versión salvo que sea estrictamente necesario y esté separado del núcleo académico.

## 5. Vista 2 — Laboratorio de algoritmos

Esta es la pantalla central del aplicativo.

Implementar:

### Entrada de datos

- Campo para ingresar un arreglo de números enteros.
- Ejemplo precargado: [-2, 1, -3, 4, -1, 2, 1, -5, 4].
- Botón para generar un arreglo aleatorio.
- Selector de tamaño.
- Selector de rango de valores.
- Semilla opcional.
- Validación de entrada.

### Ejecución

Permitir seleccionar:

- Kadane O(n).
- Fuerza bruta O(n²).
- Ambos algoritmos.

Botón "Ejecutar análisis".

### Resultados

Mostrar:

- Suma máxima.
- Subarreglo seleccionado.
- Índices de inicio y fin.
- Resultado de cada algoritmo.
- Comparación de resultados.
- Confirmación de equivalencia.
- Tiempo de ejecución individual cuando sea medible.

Para el arreglo de ejemplo, la suma máxima debe ser 6 y el subarreglo [4, -1, 2, 1].

Mostrar visualmente el arreglo, destacando los elementos que pertenecen al subarreglo óptimo.

### Explicación educativa

Agregar pestañas:

- Ejecución.
- Análisis teórico.
- Complejidad.
- Invariante.

Explicar cómo Kadane actualiza el mejor subarreglo terminado en la posición actual y el mejor valor global.

Opcionalmente, implementar una tabla paso a paso con:

- Índice.
- Elemento.
- Mejor suma terminada en la posición.
- Mejor suma global.

Esta tabla debe derivarse de una traza real del algoritmo.

### Reglas del motor

- Los algoritmos deben ser funciones Python puras, independientes de Streamlit.
- No modificar el arreglo original.
- Definir explícitamente el contrato para arreglos vacíos.
- Para esta versión, un arreglo vacío debe generar ValueError.
- Soportar arreglos con todos los elementos negativos.
- Soportar arreglos con todos los elementos positivos.
- Soportar ceros, duplicados y un solo elemento.
- No permitir resultados incorrectos derivados de inicializar el máximo en cero.
- Establecer una política determinista de desempate para subarreglos con igual suma.
- Devolver una estructura consistente con suma, índices y subarreglo.
- Mantener una función simple que devuelva solamente la suma máxima si facilita las pruebas académicas.

## 6. Implementación de algoritmos

Crear un módulo independiente:

src/audrithm/algorithms.py

Implementar:

1. kadane(arr)
2. brute_force(arr)

La implementación de fuerza bruta debe usar dos bucles anidados y una suma acumulada para garantizar O(n²), no una implementación O(n³) que recalcule cada subarreglo desde cero.

Kadane debe recorrer el arreglo una vez y utilizar memoria auxiliar O(1), excluyendo la representación del subarreglo devuelto.

Documentar:

- Precondiciones.
- Postcondiciones.
- Invariante.
- Correctitud.
- Complejidad temporal.
- Complejidad espacial.
- Política de desempate.

Mantener separada la lógica académica de la presentación.

El integrante 1 es responsable de este módulo. No atribuir su implementación a otro integrante.

## 8. Vista 4 — Experimentos

Construir un laboratorio de medición reproducible.

Requisitos obligatorios:

- Mínimo seis tamaños de entrada.
- Tamaños duplicados progresivamente.

- Semilla aleatoria fija.

- Registro de tiempos.
- Exportación CSV.

Validar que sean adecuados para el entorno.

Medir con time.perf_counter_ns().

Generar los arreglos antes de iniciar cada medición, de modo que el costo de generar datos no forme parte del tiempo del algoritmo.

Utilizar exactamente los mismos arreglos para comparar ambos algoritmos en cada tamaño y repetición.

Controlar posibles efectos del orden de ejecución.

No introducir operaciones de interfaz, escritura de archivos ni generación de gráficas dentro del intervalo medido.

- experiment_results.csv
- experiment_metadata.json

- Configuración.

## 9. Vista 5 — Resultados y análisis

Implementar visualizaciones reales a partir del CSV.

Crear:

### Gráfica 1

Tiempo de ejecución frente al tamaño de entrada en escala normal.

### Gráfica 2

Tiempo de ejecución frente al tamaño de entrada en escala log-log.

### Tabla comparativa

Mostrar:

- Tamaño n.
- Mediana Kadane.
- Mediana fuerza bruta.
- Razón T(2n)/T(n) para Kadane.
- Razón T(2n)/T(n) para fuerza bruta.

Explicar que teóricamente:

- Kadane presenta crecimiento lineal O(n).
- Fuerza bruta presenta crecimiento cuadrático O(n²).
- Para un comportamiento aproximadamente lineal, T(2n)/T(n) tiende a 2.
- Para un comportamiento aproximadamente cuadrático, T(2n)/T(n) tiende a 4.

No afirmar que las mediciones reales necesariamente producirán razones exactas de 2 o 4.

No inventar resultados.

No afirmar que un experimento demuestra matemáticamente la complejidad.

El análisis debe utilizar expresiones académicamente correctas como:

"Los resultados son consistentes con el comportamiento teórico en el rango de tamaños evaluado".

Mostrar advertencias sobre ruido experimental, resolución del reloj, calentamiento y condiciones del entorno.

Permitir descargar gráficas y resultados.
